# Pretrained model research and selection

Date: 2026-10-13. All 17 requested candidates/groups were investigated against current public cards, configs, file inventories, upstream preprocessing and documentation. No checkpoint download, model loading, inference or fine-tuning occurred. Availability means exposed public assets, not proven tensor/runtime integrity. Publisher benchmark claims are separated from independently verified transfer performance; the latter is absent for this TechDebt360 workload.

## Selected stack and decisions

**Primary candidate:** Qwen2.5-Coder-7B-Instruct for source-grounded explanations and bounded Java patch proposals, conditional on M1 runtime and M7 outcome evaluation. It is not a debt detector or effort estimator. **Optional retrieval:** CodeRankEmbed only if lexical/symbol retrieval loses the preregistered relevance and patch-outcome comparison. Baseline product measurement uses Git plus a compatible static analyzer; no authoritative learned debt detector is mandatory.

**Conditional forecast experiment:** Chronos-2-small first, full Chronos-2 capacity control and TimesFM 2.5 target-only challenger. Granite TTM-r3 must have a specific branch and enough measured context; it is not integrated merely because its weights are small. CatBoost/Ridge/Random Forest/LightGBM and persistence remain strong controls. Moirai is a noncommercial independent-univariate research comparator; Toto is a later sample-based multivariate comparator if budget warrants it. There is no measured accuracy winner and no operational forecast approval.

**Specialist screening:** Tesoro models classify Java debt types, TechDebtClassifier ranks cleaned added diffs, BEACon handles issue text. Their unresolved checkpoint licensing and validation gates keep them out of the initial active stack. CodeAid is a large generative coupling-smell specialist without documented transfer evidence; ModernBERT has unresolved defect labels/dataset; raw CodeReviewer requires task-specific preprocessing/fine-tuning; SonarSweep is a expensive Java-generation specialist. No score is converted to remediation minutes.

### Common integration/runtime policy

All adapters record model ID + immutable SHA, code/tokenizer SHA, isolated environment lock, prompt/preprocessing version, input eligibility/length, exact labels/units, raw logits and any separately fitted calibration. Current package constraints conflict across forecasters; use separate runners rather than one giant environment. Resources below distinguish raw weight size, publisher requirements and estimates. End-to-end RAM/VRAM/p50/p95 latency are **unmeasured** for every candidate. Initial benchmark budgets are single request, batch 1, four-kilobyte/short source units or a 4k-token generator context; larger-context results are a separate experiment. Cache by full source/model/preprocessing identity. Unsupported input yields ABSTAIN with a reason, never a forced clean label.

Qwen emits an explanation/candidate; its output is verified by compilation/tests and independent analyzer evidence. CodeRankEmbed emits relevance vectors/rankings; similarity proves neither debt nor duplication. Classification emits types/risk suggestions, not authoritative findings. Forecasts emit future numerical targets and uncertainty, not human labor or business priority. The detailed contracts and provenance evidence follow.

**Publication correction:** the Tesoro preprint's under-review text is stale. ACM publisher metadata identifies the TOSEM article published 2026-03-13, DOI [10.1145/3801745](https://doi.org/10.1145/3801745), corroborated by [publisher-deposited Crossref metadata](https://api.crossref.org/works/10.1145/3801745). That strengthens publication status, not checkpoint licensing or cross-project accuracy.

# Code and technical-debt model verification

Decision served: select the smallest defensible technical-debt model stack. Research only; no model weights fetched, no inference, installation, or repository implementation. Access date for every source: **2026-10-13**. Publishers are the named model owners unless indicated. HF repository creation dates below come from the live Hub API and are **repository dates, not claimed model publication dates**. Cards, configs, file inventories, upstream research, and public preprocessing code were read; hardware figures marked estimates were calculated, not benchmarked.

## Decision finding

None of these sources establishes an out-of-the-box, general technical-debt detector that is reliable across arbitrary repositories and languages. The three Tesoro checkpoints are **four-output multi-label Java debt-type classifiers**; their configs contain no explicit no-debt label. A zero vector is a permitted prediction, but is not evidence of calibrated debt absence. `TechDebtClassifier` explicitly supports a possible-debt versus probably-clean decision on **cleaned added diff lines**. BEACon-TD's collection supports **issue text**, not source-code smell detection. Defect prediction, retrieval, review generation, coupling-smell generation, and Java code generation are separate tasks; these outputs cannot safely be interpreted as interchangeable debt scores. [Tesoro configs](https://huggingface.co/NamCyan/codebert-base-technical-debt-code-tesoro/blob/main/config.json), [diff-classifier card](https://huggingface.co/davidgaofc/TechDebtClassifier), [BEACon-TD paper](https://www.sciencedirect.com/science/article/pii/S0164121225001037).

**Recommendation/inference:** begin with **zero mandatory ML detectors** in the authoritative findings path. If model-assisted explanations are a requirement, evaluate **one Qwen2.5-Coder-7B-Instruct** generator behind structured, source-cited findings and human acceptance. If semantic code retrieval materially beats lexical/symbol retrieval on a local evaluation, add **CodeRankEmbed** as the sole retrieval model. Run specialist classifiers only as optional experiments aligned with their actual input modality. This recommendation minimizes unrelated models and follows the task mismatch and uncertainty documented below; it is not an experimentally measured stack result.

**Labels:** each config explicitly sets `problem_type: multi_label_classification`, with `id2label` entries `LABEL_0` to `LABEL_3`. Each also carries an inconsistent `label2id` containing only string `0` and `1`; do not infer a binary classifier from that field. The authors' [dataset schema](https://github.com/NamCyan/tesoro/blob/main/data/README.md) documents ordered binary indicators for **DESIGN, IMPLEMENTATION, DEFECT, TEST** (schema misspells implementation). The public [training code](https://github.com/NamCyan/tesoro/blob/main/training/cross_validation.py) preserves binary vectors and predicts each output using **logit > 0**, equivalent to sigmoid > 0.5. Thus generic label names can be interpreted through the upstream schema, with a provenance caveat: no checkpoint-specific semantic mapping file was found.

**Preprocessing:** [RQ3 recipe](https://github.com/NamCyan/tesoro/blob/main/training/scripts/RQ3/run.sh) selects `cleancode`, not raw file/diff/comment input, with maximum length 512. The schema defines normalized lowercase code with newlines removed. Training code filters out examples whose encoded `cleancode` exceeds the maximum length, so silently truncating arbitrary long functions changes the evaluated setting. GraphCodeBERT is loaded as a sequence classifier with tokenized text here; no data-flow graph construction is present in this RQ3 path. Its base-model name alone is no justification for adding a graph preprocessing service. These are function-level, Java-only research candidates; project-level and other-language suitability remains unverified. [Recipe](https://github.com/NamCyan/tesoro/blob/main/training/scripts/RQ3/run.sh), [preprocessing](https://github.com/NamCyan/tesoro/blob/main/training/cross_validation.py).

**Benchmark boundary:** paper initially submitted **2024-11-08**, v2 revised **2025-08-09**, now titled *Detection of Technical Debt in Java Source Code*. Results average random 10-fold cross-validation, not a held-out-project production test. F1 around 43–44 is evidence for baseline research, not autonomous quality gates. Paper hyperparameters and current public RQ3 script differ (paper 10 epochs / 1e-5; script 20 / 2e-5); exact reproducibility of uploaded fold-zero checkpoint against reported averages remains unresolved. [Paper version/history](https://arxiv.org/abs/2411.05457), [paper experiment](https://arxiv.org/html/2411.05457v2#S5.SS2), [recipe](https://github.com/NamCyan/tesoro/blob/main/training/scripts/RQ3/run.sh).

**Licensing/dependencies:** no license declaration or LICENSE file was returned for these HF checkpoints. The [replication repository](https://github.com/NamCyan/tesoro/blob/main/LICENSE) is MIT; that is supporting evidence, not automatic proof of the fine-tuned checkpoint license. Resolve weight licensing before adoption. Public [requirements](https://github.com/NamCyan/tesoro/blob/main/training/requirements.txt) list torch, datasets, transformers, accelerate, huggingface_hub, evaluate; checkpoint configs record Transformers 4.40.2. CPU feasibility is an estimate; F32 weights alone require approximately **0.50 GB** per model. A small sequential inference workload should be evaluated on CPU before assigning a GPU; latency and total RAM are unmeasured. The cards' two A100-80GB training setup is **not** an inference requirement.

## Fair benchmark design and resource treatment

The following is a proposed protocol, not empirical findings. Use recorded measured target values and actual snapshot spacing. Freeze held-out repositories/time periods and target definition before any tuning. Rank target-only zero-shot models first; run native multivariate/covariate and fine-tuned variants separately with identical information availability. Future maintenance effort, future analysis results, and future commit attributes are unavailable covariates unless genuinely known at forecast origin. Report naive last-value, drift and justified seasonal baselines, MAE in remediation minutes, scale-free error only when its denominator is meaningful, and quantile loss/coverage on shared quantiles. Keep point median distinct from mean. Expose failure rates, missingness, constant histories, negative forecasts, abrupt analyzer-rule/coverage changes, latency, peak memory and preprocessing.

Use common rolling origins, common observations available at origin, equal horizons and common quantiles. Compare both common context and model-permitted extended context separately. Padding/interpolation/recursive extension are adapter decisions and must be disclosed; do not silently give one model additional observed history or manufacture evidence. The TTM revision must fit the chosen task's native horizon; do not reject the whole family because main forecasts only 30. Toto sample count/seed/batching and TimesFM XReg fit/normalization flags must be fixed. Use separate isolated runners because retrieved package constraints conflict.

**Resource estimates:** artifact sizes above establish storage order only. Small Chronos, TTM and Moirai are plausible inexpensive pilots from parameter/weight size, but activation memory depends on batch, context, variates and decoding; Toto's trajectory count adds another cost dimension. No authoritative minimum RAM/VRAM or comparable measured per-history runtime was established for this workload. Obtain those measurements in an explicitly authorized later benchmark; do not quote publisher throughput as a hardware guarantee.

Open questions before execution: actual observation cadence and forecast horizon; sufficient independent histories/holdout length; missing measurements versus unchanged scans; bounded/nonnegative target semantics; license-compatible purpose for Moirai; pinned package versions that load each observed SHA; exact TTM revision/output API; reproducibility and memory limits for Toto samples; whether any measured model improves over simple baselines on these targets. No incumbent winner is justified by this research alone.
