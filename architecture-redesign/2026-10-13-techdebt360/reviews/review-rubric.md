## Findings

1. **P1, AD-3 / Sonar publication boundary:** the lease rule says it prevents concurrent publication, but a second scan can replace the current issue inventory before the first export. Fix the rule to lease the same Sonar project key **from before submission through complete verified export**, or use isolated keys with enforced ownership. Fencing the metadata write alone does not protect an external service. Specify lease recovery without releasing the project to another analysis while CE state remains unknown. [Spine AD-3](../2026-10-13-techdebt360.md), [recovery section](../OPTIMAL_SYSTEM_ARCHITECTURE.md).

2. **P1, AD-11 / build-fetch-scanner boundary:** allowlisting `mvn`/`gradle` does not stop repository build scripts/plugins/tests from executing code. The design has rootless containers and restricted networking, but scanner/fetch credential placement is left open. Make the divergence rule explicit: untrusted build/test phases have no scanner/admin/fetch secrets; dependency fetch uses an isolated broker/cache; scanner submission/export is a distinct narrowly privileged phase. Also forbid generated patches from modifying verification policies or disabling tests/analyzer scope. This enforces existing trust intent, without adding distributed infrastructure. [AD-11 and remediation invariants](../2026-10-13-techdebt360.md), [deployment section](../OPTIMAL_SYSTEM_ARCHITECTURE.md).

3. **P2, auth contract:** roles are reader/analyst/approver/admin, while the research-only forecast route requires an undefined “research role.” Either define a researcher permission granted to an existing role in a separate research namespace, or add the role consistently. Avoid letting API and dashboard independently decide research visibility. [API routes and conventions](../OPTIMAL_SYSTEM_ARCHITECTURE.md).

4. **P2, capability lifecycle:** `expires_at` is present but admission on expiry is not explicit; enqueue-time approval can also become stale during long jobs. Bind a rule that lookup and publication recheck current capability version/expiry/revocation, and that an expired capability cannot produce normal-mode output. Distinguish artifact retention from current permission to display a prediction as validated. [AD-5 / AD-12](../2026-10-13-techdebt360.md), [Capability record](../OPTIMAL_SYSTEM_ARCHITECTURE.md).

5. **P2, imported-domain representation:** AD-4 requires a complete domain hash, while imported V2 cannot prove every analyzer/build parameter. Avoid synthesizing missing parameters into a falsely complete equivalent domain. Define an imported domain with explicit unknown fields, source-version/provenance hash and compatibility state; it can support bounded research under a registered approximation without becoming equivalent to a verified own domain. [Domain and imported status rules](../2026-10-13-techdebt360.md), [data contracts](../OPTIMAL_SYSTEM_ARCHITECTURE.md).

6. **P2, ranking and graph reality:** v1 uses resolved graph fan-in, but current reuse only supplies lexical imports/build literals. Document whether `D` is absent until a resolved extractor exists, or is an explicitly separate lexical proxy policy. Preserve provenance and coverage of graph edges; do not silently promote lexical coverage to resolved architecture. Define aggregation level for finding/file/module ranks so independent units do not apply factor percentiles to different populations. [Current implementation audit](../CURRENT_SYSTEM_AUDIT.md), [ranking policy](../OPTIMAL_SYSTEM_ARCHITECTURE.md).

7. **P2, measurable verification status:** AD-10 identifies `evidence-verified` but leaves the exact status predicate to builders. Bind the requirement that recorded mandatory checks all complete and pass under frozen policies, while no-test/timeout/partial checks remain partial. Human correctness and behavioral equivalence remain separate judgments; do not elevate merely green tests to all-debt-remediated. Allow recorded approval of a clearly partial patch for export only without changing its scientific status. [Verification port and approval routes](../OPTIMAL_SYSTEM_ARCHITECTURE.md).
