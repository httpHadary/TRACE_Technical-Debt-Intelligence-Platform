# Forecast checkpoint research digest

Decision: which of six exact checkpoints can enter a fair benchmark of measured software maintainability histories expressed in minutes. Research/design only; accessed 2026-10-13. No weights downloaded, packages installed, inference run, or application/configuration files changed. Fifteen successful research batches inspected primary Hugging Face metadata/configs and publisher GitHub/docs/papers. Project context supplied the question, never evidence. This is a candidate-admission assessment, not an accuracy selection.

**Verdict (research inference):** start the low-cost pilot with `autogluon/chronos-2-small`, keep `amazon/chronos-2` as its capacity control, and add TimesFM 2.5 as a univariate challenger. Toto 1.0 is an eligible multivariate/probabilistic challenger when runtime and sampling cost can be measured. TTM-r3 is eligible only after fixing a specific revision and its integration contract. Moirai 2.0 is a research-only, independent-univariate comparator because the checkpoint carries a noncommercial license. None has retrieved evidence establishing validity for software-maintainability remediation minutes; none should win admission or selection because its pretraining included telemetry.

**Critical unit/cadence distinction (design assumption):** “minutes” may denote remediation-effort units rather than observation spacing. A history sampled per scan, commit, day, or deployment is not a minutely series merely because its values are minutes. Every context/horizon below is observations, not wall-clock minutes. Cadence and horizon must be set from the measured histories before benchmarking; preserve event timestamps and never manufacture minutely observations by copying scan results.

## Evidence status

`Observed` means this run directly inspected public metadata/config/source. It verifies what a publisher exposes, not runtime correctness or independent accuracy. `Publisher assertion` means an author/model card makes the statement; medium confidence, unverified by an independent publisher. No model's accuracy, latency, memory requirement, or domain validity was independently verified here. Separate URLs under the same vendor do not count as independent corroboration. Undated living docs are explicitly undated; retrieval freshness does not establish the age of every line.

## Exact inference contracts and constraints

### Chronos 2 and Chronos 2 Small

Publisher assertion: Chronos 2 supports single/multiple targets, past-only real/categorical covariates, known-future real/categorical covariates, and cross-learning across grouped series; pandas API receives ID/timestamp/target columns plus optional future covariate frame and returns multi-step quantiles. CPU and GPU inference are documented. The small card identifies 28M parameters and shares the Chronos 2 API; full card states 120M. [Amazon card](https://huggingface.co/amazon/chronos-2) (Amazon, updated 2026-06-05; accessed 2026-10-13), [small card](https://huggingface.co/autogluon/chronos-2-small) (AutoGluon, last modified 2025-12-03; accessed 2026-10-13).

Observed configs: both use context 8192, input/output patches 16, maximum output patches 64, hence direct native horizon 1024 observations (arithmetic inference). Full has 21 quantiles; small has 13; both include 0.1/0.5/0.9. Neither config establishes a fixed calendar cadence. Benchmark arbitrary measured frequencies as regular observations, with adapter frequency handling explicitly recorded. [Full config](https://huggingface.co/amazon/chronos-2/raw/main/config.json), [small config](https://huggingface.co/autogluon/chronos-2-small/blob/main/config.json) (Amazon/AutoGluon, undated configs on revisions above; accessed 2026-10-13).

Observed runtime manifest: Python >=3.10, Torch >=2.2,<3, Transformers >=4.41,<6, Accelerate >=1.1,<2, pandas >=2,<4. Current docs use `chronos-forecasting`; pin package and model revision together. [Manifest](https://raw.githubusercontent.com/amazon-science/chronos-forecasting/main/pyproject.toml) (Amazon Science, undated living source; accessed 2026-10-13). The author's benchmark superiority/throughput claims are not independently reproduced here and are not evidence for maintainability forecasting. [Repository](https://github.com/amazon-science/chronos-forecasting) (Amazon Science, news dated 2025-10-20 and 2026-06-05; accessed 2026-10-13).

### TimesFM 2.5 PyTorch

Observed config: context_length 16384; input patch 32; output horizon block 128; quantile horizon 1024 with 0.1–0.9. Card example receives a list of 1D NumPy contexts and returns point array `(batch,horizon)` plus `(batch,horizon,10)` (mean and nine deciles). [Config](https://huggingface.co/google/timesfm-2.5-200m-pytorch/raw/main/config.json), [card](https://huggingface.co/google/timesfm-2.5-200m-pytorch) (Google, card updated 2025-10-02; accessed 2026-10-13).

Observed source: compiled context is rounded to input-patch multiples, horizon to output-block multiples; their sum must fit context_limit; continuous quantile head rejects horizons above its output size. Thus 16k is not an unconditional usable context plus arbitrary horizon. [2.5 implementation](https://raw.githubusercontent.com/google-research/timesfm/master/src/timesfm/timesfm_2p5/timesfm_2p5_torch.py) (Google Research, undated living source; accessed 2026-10-13).

Publisher assertions/current docs: 2.5 removes the frequency indicator and supports covariates via XReg (added 2025-10-29). Native multivariate/covariate claims in the current README apply to **3.0**, not this checkpoint. The old HF card's “PyPI coming soon” has been superseded by current PyPI instructions. Model weights up to 2.5 remain Apache-2.0. [Current README](https://raw.githubusercontent.com/google-research/timesfm/master/README.md) (Google Research, updates through September 2026; accessed 2026-10-13). Current manifest requires Python >=3.10, optional Torch >=2.0 and an XReg extra containing JAX/CUDA and scikit-learn; these manifest declarations do not prove every supported Torch version loads this old checkpoint. [Manifest](https://raw.githubusercontent.com/google-research/timesfm/master/pyproject.toml) (Google Research, undated; accessed 2026-10-13). Keep its baseline target-only; evaluate XReg separately as an additional per-task fitting component.

IBM's revision catalogue lists additional fixed combinations through context 3072 and horizon 720; catalogue entries beyond the checked branch are publisher-declared availability, not all individually inspected weights. ### Moirai 2.0 R Small

Observed config: patch_size 16, max_seq_len 512, num_predict_token 4, nine quantiles 0.1–0.9. These are token/block settings, not 512 raw observations; 512×16=8192 is an approximate token-equivalent raw context (estimate), not a guaranteed context-plus-horizon API limit. [Config](https://huggingface.co/Salesforce/moirai-2.0-R-small/raw/main/config.json) (Salesforce, undated; accessed 2026-10-13).

Publisher paper v3 explicitly describes independent univariate forecasting without cross-variate support. Generic Moirai2Forecast source accepts target dimensions and past/future real-feature fields and emits quantile tensors, but that signature does not override the paper's limitation or verify useful exogenous conditioning for this checkpoint. Exclude it from the native cross-variate/covariate comparison until demonstrated. [Paper v3](https://arxiv.org/html/2511.11698v3) (Salesforce authors, revised 2026-02-03; accessed 2026-10-13), [forecast source](https://raw.githubusercontent.com/SalesforceAIResearch/uni2ts/main/src/uni2ts/model/moirai2/forecast.py) (Salesforce, undated; accessed 2026-10-13). No fixed calendar cadence was established. Flexible autoregressive horizon is not evidence of equally accurate long horizons; authors explicitly report degradation at longer horizons. [Abstract/version history](https://arxiv.org/abs/2511.11698) (Salesforce authors/arXiv, 2025-11-12, revised 2026-02-03; accessed 2026-10-13).

Current runtime manifest: Python >=3.10, Torch >=2.1,<2.5, Lightning, GluonTS ~=0.14.3, NumPy ~=1.26.0; inference uses Uni2TS/GluonTS. [Manifest](https://raw.githubusercontent.com/SalesforceAIResearch/uni2ts/main/pyproject.toml), [README](https://raw.githubusercontent.com/SalesforceAIResearch/uni2ts/main/README.md) (Salesforce, undated living sources, release news August 2025; accessed 2026-10-13). Its Torch upper bound conflicts with Toto's documented >=2.5 and current TTM requirement, so one shared Python environment would be inappropriate (inference from manifests).

### Toto Open Base 1.0

Publisher card: 151M parameters; multivariate input `(variates,time)` plus masks, IDs, timestamp/interval fields; probabilistic Student-T mixture trajectories; median across 256 samples used in its study. Example 4096 context/336 horizon and 15-minute interval are examples, not fixed native limits. Config patch/stride 64. [Card](https://huggingface.co/Datadog/Toto-Open-Base-1.0), [config](https://huggingface.co/Datadog/Toto-Open-Base-1.0/raw/main/config.json) (Datadog, last modified 2026-05-14; accessed 2026-10-13).

Observed/current docs: 1.0 gained exogenous support February 2026; timestamp fields are expected by its API but README says the current 1.0 release does not use them. Therefore setting interval=60 seconds does not itself condition the model on minute cadence. Forecaster supports known-future exogenous channels placed last, injecting their values during autoregressive decoding; sample batching multiplies effective batch size, and source recommends >=128 samples for reliable forecasts. No hard maximum context/horizon was established in inspected config/forecaster; do not infer unlimited affordable context. [README](https://raw.githubusercontent.com/DataDog/toto/main/README.md) (Datadog, updates February/April 2026; accessed 2026-10-13), [forecaster](https://raw.githubusercontent.com/DataDog/toto/main/toto/inference/forecaster.py) (Datadog, undated; accessed 2026-10-13).

Docs require Python >=3.10 and Torch >=2.5, with CUDA/Ampere recommended and optional xFormers/Flash Attention for speed. Current requirements pin Torch 2.7.0; this differs from the looser README minimum. Current repository defaults discuss Toto 2.0, so keep the 1.0 package/import path and checkpoint explicit. [Requirements](https://raw.githubusercontent.com/DataDog/toto/main/requirements.txt), [1.0 README section](https://github.com/DataDog/toto#toto-10-legacy) (Datadog, requirements undated; README updates 2026; accessed 2026-10-13). BOOM/observability benchmark success is publisher evidence for that benchmark, not for remediation-minute targets.

## Fair benchmark design and resource treatment

The following is a proposed protocol, not empirical findings. Use recorded measured target values and actual snapshot spacing. Freeze held-out repositories/time periods and target definition before any tuning. Rank target-only zero-shot models first; run native multivariate/covariate and fine-tuned variants separately with identical information availability. Future maintenance effort, future analysis results, and future commit attributes are unavailable covariates unless genuinely known at forecast origin. Report naive last-value, drift and justified seasonal baselines, MAE in remediation minutes, scale-free error only when its denominator is meaningful, and quantile loss/coverage on shared quantiles. Keep point median distinct from mean. Expose failure rates, missingness, constant histories, negative forecasts, abrupt analyzer-rule/coverage changes, latency, peak memory and preprocessing.

Use common rolling origins, common observations available at origin, equal horizons and common quantiles. Compare both common context and model-permitted extended context separately. Padding/interpolation/recursive extension are adapter decisions and must be disclosed; do not silently give one model additional observed history or manufacture evidence. The TTM revision must fit the chosen task's native horizon; do not reject the whole family because main forecasts only 30. Toto sample count/seed/batching and TimesFM XReg fit/normalization flags must be fixed. Use separate isolated runners because retrieved package constraints conflict.

**Resource estimates:** artifact sizes above establish storage order only. Small Chronos, TTM and Moirai are plausible inexpensive pilots from parameter/weight size, but activation memory depends on batch, context, variates and decoding; Toto's trajectory count adds another cost dimension. No authoritative minimum RAM/VRAM or comparable measured per-history runtime was established for this workload. Obtain those measurements in an explicitly authorized later benchmark; do not quote publisher throughput as a hardware guarantee.

Open questions before execution: actual observation cadence and forecast horizon; sufficient independent histories/holdout length; missing measurements versus unchanged scans; bounded/nonnegative target semantics; license-compatible purpose for Moirai; pinned package versions that load each observed SHA; exact TTM revision/output API; reproducibility and memory limits for Toto samples; whether any measured model improves over simple baselines on these targets. No incumbent winner is justified by this research alone.
