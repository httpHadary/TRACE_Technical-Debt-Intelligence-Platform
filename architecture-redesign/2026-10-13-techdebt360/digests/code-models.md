# Code and technical-debt model verification

Decision served: select the smallest defensible technical-debt model stack. Research only; no model weights fetched, no inference, installation, or repository implementation. Access date for every source: **2026-10-13**. Publishers are the named model owners unless indicated. HF repository creation dates below come from the live Hub API and are **repository dates, not claimed model publication dates**. Cards, configs, file inventories, upstream research, and public preprocessing code were read; hardware figures marked estimates were calculated, not benchmarked.

## Decision finding

None of these sources establishes an out-of-the-box, general technical-debt detector that is reliable across arbitrary repositories and languages. The three Tesoro checkpoints are **four-output multi-label Java debt-type classifiers**; their configs contain no explicit no-debt label. A zero vector is a permitted prediction, but is not evidence of calibrated debt absence. `TechDebtClassifier` explicitly supports a possible-debt versus probably-clean decision on **cleaned added diff lines**. BEACon-TD's collection supports **issue text**, not source-code smell detection. Defect prediction, retrieval, review generation, coupling-smell generation, and Java code generation are separate tasks; these outputs cannot safely be interpreted as interchangeable debt scores. [Tesoro configs](https://huggingface.co/NamCyan/codebert-base-technical-debt-code-tesoro/blob/main/config.json), [diff-classifier card](https://huggingface.co/davidgaofc/TechDebtClassifier), [BEACon-TD paper](https://www.sciencedirect.com/science/article/pii/S0164121225001037).

**Recommendation/inference:** begin with **zero mandatory ML detectors** in the authoritative findings path. If model-assisted explanations are a requirement, evaluate **one Qwen2.5-Coder-7B-Instruct** generator behind structured, source-cited findings and human acceptance. If semantic code retrieval materially beats lexical/symbol retrieval on a local evaluation, add **CodeRankEmbed** as the sole retrieval model. Run specialist classifiers only as optional experiments aligned with their actual input modality. This recommendation minimizes unrelated models and follows the task mismatch and uncertainty documented below; it is not an experimentally measured stack result.

**Labels:** each config explicitly sets `problem_type: multi_label_classification`, with `id2label` entries `LABEL_0` to `LABEL_3`. Each also carries an inconsistent `label2id` containing only string `0` and `1`; do not infer a binary classifier from that field. The authors' [dataset schema](https://github.com/NamCyan/tesoro/blob/main/data/README.md) documents ordered binary indicators for **DESIGN, IMPLEMENTATION, DEFECT, TEST** (schema misspells implementation). The public [training code](https://github.com/NamCyan/tesoro/blob/main/training/cross_validation.py) preserves binary vectors and predicts each output using **logit > 0**, equivalent to sigmoid > 0.5. Thus generic label names can be interpreted through the upstream schema, with a provenance caveat: no checkpoint-specific semantic mapping file was found.

**Preprocessing:** [RQ3 recipe](https://github.com/NamCyan/tesoro/blob/main/training/scripts/RQ3/run.sh) selects `cleancode`, not raw file/diff/comment input, with maximum length 512. The schema defines normalized lowercase code with newlines removed. Training code filters out examples whose encoded `cleancode` exceeds the maximum length, so silently truncating arbitrary long functions changes the evaluated setting. GraphCodeBERT is loaded as a sequence classifier with tokenized text here; no data-flow graph construction is present in this RQ3 path. Its base-model name alone is no justification for adding a graph preprocessing service. These are function-level, Java-only research candidates; project-level and other-language suitability remains unverified. [Recipe](https://github.com/NamCyan/tesoro/blob/main/training/scripts/RQ3/run.sh), [preprocessing](https://github.com/NamCyan/tesoro/blob/main/training/cross_validation.py).

**Benchmark boundary:** paper initially submitted **2024-11-08**, v2 revised **2025-08-09**, now titled *Detection of Technical Debt in Java Source Code*. Results average random 10-fold cross-validation, not a held-out-project production test. F1 around 43–44 is evidence for baseline research, not autonomous quality gates. Paper hyperparameters and current public RQ3 script differ (paper 10 epochs / 1e-5; script 20 / 2e-5); exact reproducibility of uploaded fold-zero checkpoint against reported averages remains unresolved. [Paper version/history](https://arxiv.org/abs/2411.05457), [paper experiment](https://arxiv.org/html/2411.05457v2#S5.SS2), [recipe](https://github.com/NamCyan/tesoro/blob/main/training/scripts/RQ3/run.sh).

**Licensing/dependencies:** no license declaration or LICENSE file was returned for these HF checkpoints. The [replication repository](https://github.com/NamCyan/tesoro/blob/main/LICENSE) is MIT; that is supporting evidence, not automatic proof of the fine-tuned checkpoint license. Resolve weight licensing before adoption. Public [requirements](https://github.com/NamCyan/tesoro/blob/main/training/requirements.txt) list torch, datasets, transformers, accelerate, huggingface_hub, evaluate; checkpoint configs record Transformers 4.40.2. CPU feasibility is an estimate; F32 weights alone require approximately **0.50 GB** per model. A small sequential inference workload should be evaluated on CPU before assigning a GPU; latency and total RAM are unmeasured. The cards' two A100-80GB training setup is **not** an inference requirement.

## 4. davidgaofc/TechDebtClassifier

These numbers must not be compared directly with Tesoro or issue-text performance.

The publisher's [Space app.py](https://huggingface.co/spaces/davidgaofc/TechDebtPipeline/blob/main/app.py) takes only diff lines beginning with `+`, excludes `+++` headers, removes `+`, rejoins with newlines, and rejects added text beyond roughly 2,000 characters. It treats cleaning and classification as separate UI operations. This supplies a reproducible cleaning interpretation, but no full training pipeline and no proof that all training examples used this precise limit. The card records Transformers 4.35.0, torch 2.1.0+cu118 and Tokenizers 0.14.1. **Disposition: optional diff-ranking experiment**, after license clarification and representative positive/negative diff evaluation; inappropriate as a whole-file or repository debt detector.

## Adoption gates and unresolved evidence

1. Define the actual evaluated unit: normalized Java function (Tesoro), added diff lines (TechDebtClassifier), issue body (BEACon), classes/dependencies (CodeAid), edit context (CodeReviewer), or retrieval query/snippet (CodeRankEmbed). Do not run a single input adapter across these tasks.
2. Recover checkpoint-specific labels and explicit license grants for Tesoro, davidgaofc and karths before model adoption. Distinguish an omitted type from verified debt absence. ModernBERT's 0/1 semantic mapping is unresolved.
3. Evaluate project-disjoint positive and negative examples, including clean code, rare types, long functions, generated/vendor code, contradictory comments, missing dependency context and unsupported languages. Report precision/recall per modality/type, abstention, calibration and false-positive rate; existing publisher metrics are not comparable across tasks.
4. Benchmark only the shortlisted optional model(s), using pinned revisions, bounded context and actual hardware. All calculated weight sizes above use decimal GB and exclude runtime, tokenizers, activations, KV caches, optimizer state and index storage. Quantized sizes are theoretical payload lower bounds, not proof an exact quantized artifact or runtime works.
5. Verify source-grounded explanations/patch correctness separately from classification. None of the listed classifier benchmarks establishes remediation cost, debt interest, business priority, repository-level aggregation or safe autonomous changes.

Research source quality: configs/API/file trees directly verify architecture and artifacts; cards verify **publisher claims**, not independent efficacy; upstream papers give task/evaluation context. No independent production benchmark for these exact checkpoints was found in this scoped pass. No project documents were used as factual research evidence.
