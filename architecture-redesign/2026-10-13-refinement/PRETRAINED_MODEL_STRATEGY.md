# Pretrained model strategy

Date: 2026-10-13. **Pretrained AI remains central to the proposed research and platform. The provisional complementary stack is one Java classifier, CodeRankEmbed retrieval, Qwen generation and one numerical forecaster.** Selection depends on Experiments A and B, including local validation. Published leaderboard scores do not select a winner. No weights were downloaded, and no inference or training was run.

All 11 requested checkpoints were freshly checked through primary cards, configs, APIs and source. The [reverification digest](digests/model-reverification.md) records detailed contracts, immutable revisions, weight hashes and primary sources, all accessed on 2026-10-13. Public assets establish availability; successful loading and local efficacy remain unverified. An unknown checkpoint license is an unresolved adoption condition, not evidence of prohibition or model failure.

Research priority does not authorize execution. Keep `BLOCKED_LICENSE`, `BLOCKED_DATA`, `LOAD_FAILED`, `RESEARCH_ADMITTED` and `PRODUCT_VALIDATED` distinct. A candidate may be admitted to research planning while weight execution remains blocked by licensing. A static fallback preserves usefulness but does not complete the pretrained classification experiment.

### Classifier semantics and output handling

For both Tesoro checkpoints, the exact configs declare `multi_label_classification` and `id2label` entries `LABEL_0` through `LABEL_3`, but contain an inconsistent two-entry `label2id`. Do not infer a binary classifier from that field. The author dataset schema supplies the ordered vector **DESIGN, IMPLEMENTATION, DEFECT, TEST**; no checkpoint-specific semantic mapping file was found. Treat this as a provenance-backed mapping that still needs a load/output-contract check. [Exact Graph config](https://huggingface.co/NamCyan/graphcodebert-base-technical-debt-code-tesoro/blob/edb7d422be19fe6cc420e01eed154225bb4cdfd8/config.json), [exact Code config](https://huggingface.co/NamCyan/codebert-base-technical-debt-code-tesoro/blob/849dd197ba21ba88651d400af95103c5bc30e21e/config.json), [author schema](https://github.com/NamCyan/tesoro/blob/main/data/README.md).

Apply sigmoid independently to each of the four logits; do not use softmax across labels. The author's prediction threshold is logit > 0, equivalent to sigmoid > 0.5. Sigmoid scores are not proven calibrated probabilities. An all-zero vector is a permitted output, not evidence of calibrated debt absence. Preserve raw function text, source locations, normalized text and token-length admission separately. The study excludes overlength functions; silently truncating arbitrary functions changes the evaluated setting. [Author training and prediction source](https://github.com/NamCyan/tesoro/blob/main/training/cross_validation.py).

For TechDebtClassifier, use its single-label contract rather than Tesoro's independent-label threshold. Its semantic binary mapping comes from the model card, not the config. Neither classifier establishes file-level remediation effort, debt interest or autonomous remediation correctness. Resolve weight licensing before execution or adoption; the Tesoro code repository's MIT license and a companion Space's license do not automatically license checkpoint weights.

No metrics above were produced by TechDebt360 during this task. Do not compare classification F1, retrieval MRR, forecast MAE and generation scores as one accuracy ranking. Primary sources and benchmark dates are recorded in the digest.

## Forecast tensors and cadence

For the proposed forecasting adapter, normalize each single-target series to point output `(B, H)` and selected quantiles `(B, H, Q)`, with explicit quantile levels and point semantics. This is an application contract; each native return structure must be checked before conversion. Chronos full and small share 0.1/0.5/0.9. TimesFM's ten-column output contains a mean followed by deciles. TTM's inspected source places the quantile axis before time and channel; it must be transposed and the single channel handled explicitly.

Observation cadence and target units are separate: remediation minutes do not imply minutely observations. Chronos DataFrame input requires a regular timestamp grid; an explicit frequency argument is not checked against the data. Underlying Chronos source detects NaNs or a context mask. Preserve missing measurements rather than substituting interpolated ground truth. Known-future covariates must genuinely be available at the forecast origin. [Chronos pipeline](https://github.com/amazon-science/chronos-forecasting/blob/main/src/chronos/chronos2/pipeline.py), [model masking](https://github.com/amazon-science/chronos-forecasting/blob/main/src/chronos/chronos2/model.py).

## TTM: branch and loader decisions

| Task | Branch | Exact revision | Input/output policy |
|---|---|---|---|
| Weekly 13 steps / 91 days | `52-16-dec-52-r3` | `7d99b7e35b3dc18f9db3b2b73cc9699dea6c9508` | 52 real weekly observations → native 16-step forecast; crop the first 13 steps. |
| Daily 30 days | `90-30-dec-90-r3` | `417bfc83545095031c2a002ddfe73ac6b700ea1a` | 90 real daily observations → 30 steps. |
| Daily 60 days | `180-60-dec-180-r3` | `1ec010e9aca3da90fc5159d109749ae96b01806e` | 180 real daily observations → 60 steps. |
| Daily 90 days | `512-96-dec-512-r3` | `7b070728ff280ee2bb682bd8dfbe71da21ca2c7c` | 512 real daily observations → native 96-step forecast; crop the first 90 steps. |

These are exposed branch weights/configs, not completed load tests. A complete origin requires the branch's real context plus the requested future evaluation observations; repeated rolling origins require more history. Missing-input masks cannot create additional measured history or future labels. A grid point inferred from an unchanged repository state must be identified as such and assessed separately from a newly measured observation. Repeated values may be legitimate, but do not boost the count of independent samples. The main checkpoint's 512 → 30 config does not establish a family-wide 512-observation minimum. [IBM refs](https://huggingface.co/api/models/ibm-granite/granite-timeseries-ttm-r3/refs), [branch register and weight hashes](digests/model-reverification.md#weight-bearing-ttm-branches-for-actual-cadences).

Select the **explicit decomposed prediction class** and immutable revision for these branches. Current `get_model` uses `-dec-` in the revision string for class dispatch; passing a bare SHA through that selector can select the ordinary prediction class. The default `prefer_known_mappings=True` can also choose a longer branch. Direct selection with `prefer_known_mappings=False` avoids that mapping preference, but immutable pinning should still preserve the explicit class, for example `TinyTimeMixerForDecomposedPrediction.from_pretrained(model_id, revision=SHA)`. This is a proposed runner contract, not a verified loading recipe. Record the IBM source commit and check class, config, tensor shapes and output semantics before benchmarking. [Pinned loader](https://github.com/ibm-granite/granite-tsfm/blob/3d92535ca4138648b9d1e2f3f1421b5dec4dc3aa/tsfm_public/toolkit/get_model.py).

Use past values and boolean masks shaped `(B, L, K)`. Missing NaNs replaced by zero must have false masks; without a mask, the inspected TTM source assumes all values are observed. The checked branch configs use `num_input_channels=1` and null exogenous indices. Point output is `(B, H, K)`; the inspected quantile head/source uses `(B, Q, H, K)`. Config quantiles are 0.1 through 0.9. Shape and head behavior still require a runtime check for the pinned branch/package pair. Mask-aware scaling does not establish that LOWESS decomposition is robust to filled gaps; begin with a sufficiently complete cohort and report missingness sensitivity separately. [Pinned model source](https://github.com/ibm-granite/granite-tsfm/blob/3d92535ca4138648b9d1e2f3f1421b5dec4dc3aa/tsfm_public/models/tinytimemixer/modeling_tinytimemixer.py).

Obtain full native output and explicitly crop the time axis of both point and quantile tensors after checking their shapes. Prediction filtering exists in the source, but its behavior across all pinned heads has not been tested. Cropping a native forecast is a restriction to real forecast steps; recursive extension is a different forecasting protocol. Interpolating 13 weekly ground-truth targets into 90 daily labels is not an equivalent evaluation.

The checked TTM config has `mq_q50_type="mean"`; its 0.5 slot must not be assumed to be a calibrated statistical median. Record point semantics without renaming that slot. Use 0.1/0.9 for the common interval comparison; median-specific comparisons require an appropriate declared and verified median output. Coverage, quantile crossing and local accuracy remain measurements to obtain, not properties established by the model card.

## Promotion without premature exclusion

Research admission requires source-backed assets, task fit and an explicit plan for unresolved contracts. Execution admission additionally requires permission to use the checkpoint weights, sufficient data and a verified runner. Product promotion requires held-out local benefit, calibration where claimed, runtime measurements and failure handling. A missing license, insufficient data or absent host prerequisite must not be recorded as poor model performance.

Experiment A compares the provisional small Chronos model with full Chronos, eligible TTM branches, TimesFM 2.5 and conventional baselines on matched origins, targets and horizons. Retain at most one forecasting model per validated target/domain after the comparison. If a conventional predictor wins, report that outcome while preserving the distinction between completed AI research and product deployment.

Experiment B compares GraphCodeBERT with CodeBERT on Java function labels, retrieval with lexical/symbol controls, and Qwen remediation with matched evidence ablations. Diff classification and coupling generation use their own task-specific studies. Retain one classifier, one retrieval policy/model and one generator only if each adds measurable value. Classifier scores remain annotations; measured findings and human confirmation remain distinct. Do not convert function probabilities into file-level effort, semantic distance into debt, or forecast remediation minutes into actual repair labor.

CodeAid and SonarSweep remain available candidates with separate task and resource gates. A same-task, same-budget study may justify replacing an existing role; availability alone does not justify two additional permanent generators. Hardware cost, independent correctness and reviewer utility are part of selection.

The next scientific step is to execute the two registered experiments under a separately authorized execution task. This planning work does not grant permission to load models, scan, train or patch the project.
